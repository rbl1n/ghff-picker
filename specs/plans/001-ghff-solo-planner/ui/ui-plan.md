# 前端 / UI 與靜態雛形規劃

## 介面範圍

- 目標系統介面：`選片排程網頁（web）`
- 需求來源：`spec.md 使用者故事 1～5、NFR-002、NFR-004；features/acceptance/*.feature`
- 上游依據：`plan.md（Wave 2）、research.md 決策 3／5、specs/truth/data/data-model.dbml`
- 產出順序：`先定稿本檔，再產出 ui/index.html、ui/availability.html、ui/itinerary.html、ui/tickets.html、ui/share.html`

## 視覺方向

- 風格來源：`影展紙本場次表與票根；不使用金馬官方商標、配色或字樣`
- 本次風格結論：`深色底（戲院暗場）＋暖金強調色，資訊密度高但層級清楚的「票夾」風格；支援淺色模式`
- 視覺重點：`日期與開演時間最醒目；層級用色塊（必看＝暖金實心、想看＝金框、有空再看＝灰框）；★ 影人出席用小徽章`
- 審美原則：`手機優先、單欄；觸控目標至少 44px；數字用等寬字；不靠顏色單獨表達狀態（同時有文字）`

## 畫面與流程

全站底部固定 5 個分頁：選片、時段、行程、搶票、分享；右上角另有「分享」捷徑。（實作階段由 4 個分頁 + 右上角分享調整而來，2026-10-24）

### 1. `選片`

- 對應雛形檔案：`ui/index.html`
- 主要目的：`以影片為單位瀏覽所有場次與標記，並把片分成必看／想看／有空再看（FR-002～FR-004）`
- 進入條件：`開啟工具即進入；首次開啟時所有片為未標記`
- 主要操作：`搜尋片名；依層級篩選（全部／已標記／未標記）；每部片卡片上點選三層之一或取消；展開卡片看全部場次；點熱門開關（FR-015）；標記說明（★◆▲⊚）收在頁首「標記說明」`
- 成功流轉：`標記後卡片即時改色，頁首計數更新（必看 n／想看 n／有空再看 n）；按「排行程」進入行程`
- 失敗回饋：`場次資料載入失敗時顯示「場次資料載入失敗，請重新整理」與重試按鈕`

### 2. `時段`

- 對應雛形檔案：`ui/availability.html`
- 主要目的：`設定不可看時段與每日上限（FR-005、FR-007、FR-011）`
- 進入條件：`底部分頁「時段」`
- 主要操作：`影展日期以日曆格列出，可多選日期；對選取日期「加入不可看時段」（起訖時間）或「整天不可看」；每天列出已設時段並可刪除；每日上限輸入框（空白＝不設上限）`
- 成功流轉：`套用後被選日期即時顯示新時段；選片頁的場次同步標「不可看」`
- 失敗回饋：`結束時間早於或等於開始時間時，套用按鈕停用並顯示「結束時間需晚於開始時間」；每日上限只接受 0 以上整數`

### 3. `行程`

- 對應雛形檔案：`ui/itinerary.html`
- 主要目的：`呈現最佳行程與未排入必看片原因（FR-008、FR-012、FR-013、FR-014）`
- 進入條件：`按「排行程」或底部分頁；任何輸入變更後顯示「條件已變更，重新排程」橫幅`
- 主要操作：`依日期分組的時間軸：開演–散場、片名、影廳（影城）、層級色塊、★、「非售票」標籤；頂部摘要（排入必看 x/y、想看 x/y、有空再看 x/y）；「重新排程」`
- 成功流轉：`排程中顯示進度（最多 10 秒，NFR-001）；完成後顯示行程；按「看搶票清單」到搶票`
- 失敗回饋：`有必看排不下時，頂部紅框「有 n 部必看排不進去」，逐筆列片名與原因（沒有可看場次／與「片名」衝堂／受每日上限限制）；沒有任何已標記影片時顯示空狀態「先到選片頁標記想看的片」`

### 4. `搶票`

- 對應雛形檔案：`ui/tickets.html`
- 主要目的：`開賣當下照順序搶票，並快速切換備案（FR-015～FR-021、NFR-002、NFR-003）`
- 進入條件：`行程已產生`
- 主要操作：`清單每列：順序、片名、層級、目前要搶的場次（日期 開演 影廳 ★）、兩顆大按鈕「搶到」「沒搶到」、展開看全部備案；拖曳或上下箭頭調整順序；已處理列可「撤銷」`
- 成功流轉：`按「搶到」→ 該列轉綠、鎖定並沉到已完成區；按「沒搶到」→ 同一列立即換成下一個相容備案並短暫高亮（1 次點擊，NFR-003）；全部完成後頂部顯示「搶到 n 部、未搶到 m 部」與「依搶到結果重新排程」`
- 失敗回饋：`備案用完 → 該列轉灰並顯示「已無可用場次」；排程時就沒有備案 → 顯示「無不衝堂備案」`

### 5. `分享`

- 對應雛形檔案：`ui/share.html`
- 主要目的：`把目前設定帶到另一台裝置（FR-018）`
- 進入條件：`任一頁右上角「分享」`
- 主要操作：`顯示 QR code 與「複製連結」；說明一行「用手機掃描，在手機上打開同一份清單」`
- 成功流轉：`手機開啟連結 → 出現確認「要用這份設定取代此裝置的設定嗎？」→ 確認後進入搶票頁`
- 失敗回饋：`連結損毀或版本不符時顯示「這個分享連結無法讀取，請在原裝置重新產生」`

## 互動與假資料原則

- 假資料策略：`使用 features/acceptance 中的片名與場次（夜行列車、春之祭、海邊的房間、紅色沙漠、北方、小城之春、家族之味、映後座談），讓雛形與驗收劇本對得上`
- 互動原則：`雛形以分頁連結換頁；搶票頁用少量 inline script 示範「沒搶到 → 換備案」與「搶到 → 鎖定」`
- 內容原則：`只放使用者會看到的字；時間一律 24 小時制 HH:MM；日期顯示「11/15（日）」`

## 狀態與資訊揭露

- 使用者可見資訊：`場次全部欄位與標記；層級；可看／不可看；行程；未排入原因；搶票順序、目前場次、備案、搶票狀態`
- 必須隱藏資訊：`排程演算法細節與分數；內部 id`
- 主要 UI 狀態：`場次資料載入中／失敗；未標記任何片（空狀態）；條件已變更待重排；排程中；有必看排不下；搶票列：未處理／搶到／沒搶到切換中／已無可用場次`
- 角色或權限差異：`無（單一使用者，CL-001）`

## 驗證與錯誤回饋

- 輸入驗證：`時段結束需晚於開始；每日上限為 0 以上整數或空白`
- 狀態衝突處理：`開啟分享連結時若本機已有設定，先確認再覆蓋；輸入變更後行程標「條件已變更」，不自動覆蓋已顯示的行程`
- 使用者可理解錯誤訊息：`一律中文、說明下一步怎麼做，不顯示技術錯誤碼`

## 靜態雛形輸出規劃

- 多頁入口：`ui/index.html（選片頁）即產品入口`
- 預計輸出檔案：`ui/index.html、ui/availability.html、ui/itinerary.html、ui/tickets.html、ui/share.html、ui/styles.css`
- 換頁原則：`底部分頁列在每頁一致，連到對應 html`
- Review 目標：`用手機寬度（390px）走完 選片 → 時段 → 行程 → 搶票（含沒搶到換備案）→ 分享`

## 前端實作切分建議

- 頁面 / 容器切分：`App（分頁路由）＋ FilmsPage、AvailabilityPage、ItineraryPage、TicketsPage、SharePage`
- 共用元件或區塊：`BottomTabs、FilmCard、SessionRow（時間＋影廳＋標記）、TierPicker、MarkBadge、ReasonList`
- 對後端契約的依賴：`無後端；依賴 src/domain 排程引擎與 src/state 保存／分享模組（data-model.dbml）`
- 驗收重點：`手機寬度不需左右捲動（NFR-002）；「沒搶到」一次點擊換備案（NFR-003）；未排入原因文字與 acceptance 一致`
