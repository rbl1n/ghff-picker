# 功能規格：兩人合併選片排程

**功能分支**: `002-ghff-duo-merge`

**建立日期**: 2026-10-24

**狀態**: 草稿

**輸入**: 使用者描述：「如果要結合二個人的選片結果來排的話呢？現在可以做這個嗎？結果要保存下來。」

延續 001（個人選片排程，已上線 https://rbl1n.github.io/ghff-picker/）。001 的 CL-001 把兩人合併延到後續 plan，本 plan 承接。

Clarify Round 1 拍板（2026-10-24）：

- **CL-201**：合併只排「兩人都有分層」的影片；層級取兩人中較高者（必看 > 想看 > 有空再看）。只有一方分層的影片不排入一起看的行程。
- **CL-202**：以分享連結交換資料、結果存在各自裝置（延用 001 的 localStorage + 分享連結，無後端）。合併結果可再產生連結傳給對方，對方開啟後保存在自己的裝置。
- **CL-203**：開賣時一人負責買兩張；搶票清單每列標示「買 2 張」。流程精簡：`/specify` → `/spec-by-example` → truth feature 與 DSL → `/tasks` → 實作，略過 `/system-analysis` 與 `/ui-plan` 雛形，開賣後補。

## 範圍

本版做：把同伴的分享連結以「同伴」身分加入（不取代自己的設定）、兩人姓名、依 CL-201 合併後排程、兩人搶票清單（買 2 張）、產生並開啟「合併結果連結」、移除同伴回到個人模式。

本版不做：雲端同步與即時共編（CL-202）；兩人分工各搶不同片（CL-203）；一起看之外各自的個人行程；三人以上。

## 對既有 truth 的影響

| 意圖 | 既有行為 | 本 plan 後 |
| --- | --- | --- |
| MODIFY | 開啟分享連結只能「取代此裝置的設定」 | 開啟個人分享連結時可選「取代我的設定」或「當作同伴加入」；開啟合併結果連結時只能取代 |
| MODIFY | 排程輸入為單人的分層、時段、每日上限 | 有同伴時，排程輸入為兩人合併後的結果（FR-205～FR-208）；沒有同伴時與 001 完全相同 |
| MODIFY | 搶票清單每列為一張 | 有同伴時每列標示「買 2 張」 |
| ADD | — | 姓名、同伴資料、合併結果連結、移除同伴 |

## 使用者情境與測試 *(必填)*

### 使用者故事 1 - 把同伴的選片加進來，不蓋掉自己的 (Priority: P1)

作為要和女友一起看影展的人，我希望打開她傳來的分享連結時，可以選擇把她的選片「當作同伴加入」，而不是取代我自己的設定，以便兩人的選片同時存在我的工具裡。

**為何為此優先級**: 沒有兩份資料同時存在，就無從合併；這是整個 plan 的入口。

**獨立驗證方式**: A 裝置已有自己的分層；開啟 B 的個人分享連結並選「當作同伴加入」、輸入姓名；確認 A 自己的分層不變，且畫面顯示兩人模式與同伴姓名。

**舉例說明**:

開啟同伴的個人分享連結時，確認畫面：

```
這是「小美」的選片。
[ 當作同伴加入 ]  [ 取代我的設定 ]  [ 取消 ]
```

加入後各頁頂部顯示：

```
兩人模式：Fischer ＋ 小美    [ 移除同伴 ]
```

**驗收情境**:

1. **Given** 裝置上已有自己的分層，**When** 開啟同伴的個人分享連結並選「當作同伴加入」，**Then** 自己的分層、時段、每日上限不變，同伴的分層、時段、每日上限另存為同伴資料，並進入兩人模式。
2. **Given** 開啟個人分享連結，**When** 選「取代我的設定」，**Then** 行為與 001 相同（以連結內容取代此裝置設定）。
3. **Given** 已有同伴，**When** 再開啟另一份個人分享連結並選「當作同伴加入」，**Then** 系統先確認「要用這份取代目前的同伴嗎？」，確認後取代同伴資料。
4. **Given** 兩人模式，**When** 按「移除同伴」並確認，**Then** 同伴資料刪除、回到個人模式，自己的設定不變。
5. **Given** 第一次進入兩人模式且尚未設定姓名，**When** 加入同伴，**Then** 系統要求輸入自己與同伴的顯示名稱（預設「我」與「同伴」）。

**功能需求（FR）**:

- **FR-201**: 開啟個人分享連結時，系統 MUST 提供「當作同伴加入」「取代我的設定」「取消」三個選項。
- **FR-202**: 「當作同伴加入」MUST NOT 改變此裝置自己的分層、熱門、時段、每日上限、手動順序與搶票標記。
- **FR-203**: 同一時間 MUST 最多一位同伴；加入新同伴前 MUST 確認取代。
- **FR-204**: 使用者 MUST 能移除同伴回到個人模式；移除 MUST NOT 影響自己的設定。
- **FR-209**: 兩人模式 MUST 保存兩人的顯示名稱，並在各頁頂部顯示「兩人模式：{自己} ＋ {同伴}」。

### 使用者故事 2 - 依兩人共同的片排出一起看的行程 (Priority: P1)

作為要和同伴一起看的人，我希望工具只挑兩人都有標的片、取兩人中較高的層級、避開任一人不能看的時段，排出一起看的最佳行程，以便不用兩人來回對時間。

**為何為此優先級**: 這是本 plan 的核心價值；搶票清單建立在這份行程上。

**獨立驗證方式**: 準備兩人分層與時段不同的資料，確認行程只含共同影片、層級取高、避開兩人各自的不可看時段、每日上限取較嚴者。

**舉例說明**:

| 片名 | Fischer | 小美 | 合併後 |
| --- | --- | --- | --- |
| 紅色沙漠 | 必看 | 想看 | 必看 |
| 北方 | 想看 | 有空再看 | 想看 |
| 小城之春 | 必看 | （未標記） | 不排入 |
| 家族之味 | （未標記） | 必看 | 不排入 |
| 夜行列車 | 有空再看 | 有空再看 | 有空再看 |

小美 11/12 整天不能看、Fischer 11/13 09:00–18:00 不能看：合併後兩段都不能看。Fischer 不設上限、小美每天最多 2 部：合併後每天最多 2 部。

**驗收情境**:

1. **Given** 上表兩人的分層，**When** 兩人模式下排程，**Then** 只有紅色沙漠（必看）、北方（想看）、夜行列車（有空再看）參與排程。
2. **Given** 兩人各自設定了不可看時段，**When** 排程，**Then** 任一人不可看的時段內的場次都不排入。
3. **Given** 一人不設上限、另一人上限 2，**When** 排程，**Then** 每天最多 2 部。
4. **Given** 任一人把共同影片標為熱門，**When** 產生搶票清單，**Then** 該片視為熱門。
5. **Given** 兩人模式，**When** 檢視行程頁，**Then** 頂部顯示「只有 {自己} 標記：n 部、只有 {同伴} 標記：m 部（不排入）」。
6. **Given** 兩人沒有任何共同分層的影片，**When** 排程，**Then** 顯示空狀態「兩人沒有共同標記的片，先到選片頁一起挑」。

**功能需求（FR）**:

- **FR-205**: 兩人模式下，系統 MUST 只排兩人都有分層的影片；合併層級 MUST 為兩人層級中較高者。
- **FR-206**: 合併不可看時段 MUST 為兩人不可看時段的聯集。
- **FR-207**: 合併每日上限 MUST 為兩人有設定者中的最小值；兩人都未設定則不設上限。
- **FR-208**: 合併熱門 MUST 為任一人標熱門即為熱門。
- **FR-210**: 行程頁 MUST 顯示只有單方標記而未排入的影片數。
- 排程演算法、未排入原因、相容規則沿用 001（FR-008～FR-013），輸入改為合併結果。

**狀態與公式**:

```
共同影片 = { f | 自己.tier(f) ≠ 無 且 同伴.tier(f) ≠ 無 }
合併層級(f) = max(自己.tier(f), 同伴.tier(f))，必看 > 想看 > 有空再看
合併熱門(f) = 自己.hot(f) 或 同伴.hot(f)
合併不可看 = 自己.不可看 ∪ 同伴.不可看
合併每日上限 = min(有設定的上限)；皆未設定 = 不設
```

### 使用者故事 3 - 一人買兩張的搶票清單 (Priority: P1)

作為負責搶票的人，我希望兩人模式的搶票清單每一列都標示「買 2 張」，順序、備案與標記切換照舊，以便開賣時一次買齊兩人的票。

**為何為此優先級**: 開賣當下的直接價值；建立在故事 2 的行程上。

**獨立驗證方式**: 兩人模式產生搶票清單，確認每列顯示「買 2 張」，順序與備案依合併資料計算；個人模式不顯示張數。

**驗收情境**:

1. **Given** 兩人模式且已排程，**When** 開啟搶票清單，**Then** 每列顯示「買 2 張」，順序依 001 規則以合併層級與合併熱門計算。
2. **Given** 個人模式，**When** 開啟搶票清單，**Then** 不顯示張數，與 001 相同。
3. **Given** 兩人模式，**When** 標記搶到／沒搶到，**Then** 行為與 001 相同，備案以合併後的條件判斷。

**功能需求（FR）**:

- **FR-211**: 兩人模式的搶票清單每列 MUST 顯示「買 2 張」；個人模式 MUST NOT 顯示張數。

### 使用者故事 4 - 把合併結果傳給同伴並各自保存 (Priority: P2)

作為合併好行程的人，我希望產生一個「合併結果連結」傳給同伴，她打開後就看到同一份行程與搶票清單，並存在她的裝置上，以便兩人手上都有同一份結果。

**為何為此優先級**: 讓兩人都保存結果（CL-202）；不影響合併與搶票本身能否運作。

**獨立驗證方式**: A 在兩人模式產生合併結果連結；B 用另一個瀏覽器開啟並確認；B 的行程與搶票清單與 A 一致，重新開啟仍在。

**舉例說明**:

B 開啟合併結果連結時：

```
這是「Fischer ＋ 小美」的合併結果。
開啟後會取代此裝置目前的設定。
[ 取代並開啟 ]  [ 取消 ]
```

**驗收情境**:

1. **Given** 兩人模式，**When** 開啟分享畫面，**Then** 產生的連結與 QR 標示「合併結果連結」，內容包含兩人資料、姓名、手動順序與搶票標記。
2. **Given** 另一台裝置開啟合併結果連結，**When** 選「取代並開啟」，**Then** 該裝置進入兩人模式，行程與搶票清單與產生端一致；關閉後重開仍保留。
3. **Given** 開啟合併結果連結，**When** 檢視選項，**Then** 不提供「當作同伴加入」。

**功能需求（FR）**:

- **FR-212**: 兩人模式下的分享連結 MUST 包含兩人資料與姓名，並標示為合併結果。
- **FR-213**: 開啟合併結果連結時 MUST 只提供「取代並開啟」與「取消」。

---

### 邊界情況

- 當同伴連結損毀或版本不符時，顯示 001 的錯誤訊息，不改變任何資料。
- 當同伴分層的影片不在此裝置的場次資料中時，忽略該影片。
- 當兩人模式下修改自己的分層或時段時，行程顯示「條件已變更，重新排程」（沿用 001）；同伴資料只能透過重新加入同伴連結更新。
- 當移除同伴時，已有的搶票標記保留。

## 需求 *(必填)*

### 全域需求

#### 功能需求

- **FR-214**: 同伴資料與姓名 MUST 與使用者狀態一起保存在此裝置，關閉後重開保留（延伸 001 FR-022）。

### 關鍵實體

- **同伴（partner）**: 顯示名稱、分層與熱門、不可看時段、每日上限；同一時間最多一位。
- **顯示名稱**: 自己與同伴各一。
- **合併結果**: 由自己與同伴資料依「狀態與公式」推導，不另外保存；排程與搶票清單以它為輸入。

## 假設

- 兩人使用同一份場次快照（同一個網址）。
- 同伴的搶票標記不合併；搶票由一人負責（CL-203）。
- 合併結果連結會取代接收端設定；接收端若要保留自己原本的個人設定，需先自行分享備份。
- 本 plan 不加後端（CL-202）。
- 個人分享連結帶有分享者自己的顯示名稱；未設定時確認畫面顯示「這是同伴的選片。」，姓名輸入預設「我」與「同伴」。
- 移除同伴時只清除同伴名稱，保留自己的名稱；確認文字為「要移除同伴「{同伴名稱}」嗎？」。
